# عالم البكلاوه | Alem Al Bklawa — المتجر الإلكتروني

متجر إلكتروني عربي (RTL) حقيقي للبكلاوه والحلويات والعصائر وباقات المناسبات، مع لوحة إدارة كاملة.
**Node.js + SQLite بلا أي اعتماديات خارجية** (`node:sqlite` المدمج في Node 22) — يُنشر بأمر واحد.

> هذا المجلد مستقل تمامًا عن منصة «ابتكار» في جذر المستودع؛ لم يُعدَّل شيء من المنصة ولا من قاعدة Supabase الخاصة بها.

## التشغيل المحلي

```bash
cd alem-al-bklawa
ADMIN_EMAIL=owner@example.com ADMIN_PASSWORD='كلمة-مرور-طويلة-فريدة' npm start   # يُنشئ المدير الأول عند أول تشغيل
# → http://localhost:3000        المتجر
# → http://localhost:3000/admin  لوحة الإدارة
```

- لا توجد كلمة مرور افتراضية. بدون `ADMIN_*` شغّل `npm run create-admin` بنفس المتغيرات.
- `npm run seed:demo` يضيف بيانات **وهمية للتطوير فقط** (يرفض العمل في الإنتاج). المتجر الحقيقي يبدأ **بلا منتجات**: تُدخلها من الإدارة.

## ما الجاهز في المتجر

**للعميل:** شاشة بداية بالشعار (دائرة على خلفية عنابية، دوران بطيء، خط تحميل يعكس التحميل الفعلي، مرة واحدة لكل جلسة، تحترم تقليل الحركة) · بانر إعلاني متغيّر كل 2.5 ث (قابل للضبط) بصور من الإدارة · أقسام نصية أفقية (الكل/بكلاوه/عصير/حلويات/منتجات أخرى/باقات المناسبات) تُغيّر المنتجات بلا إعادة تحميل · منتجات بأحجام لكل منها سعر · بحث عربي ذكي (يتجاوز التشكيل وأشكال الألف والتاء المربوطة وبقلاوة/بكلاوة والـ«ال») · سلة تُحفظ (وتُستعاد من الحساب على أي جهاز) وتُعاد تسعيرتها من الخادم · باقات مناسبات (بالسلة أو عبر واتساب سوق الجمعة: يُسجَّل الطلب أولًا ثم رابط واتساب برسالة جاهزة، ولا يُدّعى التأكيد) · إتمام الطلب (فرع، استلام/توصيل إن فُعّل، ملاحظات، دفع) مع كشف تغيّر السعر قبل التأكيد ومنع التكرار · صفحة الطلب وتتبّعه (برقم الطلب + الهاتف للضيف) · حسابات (تسجيل/دخول/خروج/تعديل/كلمة المرور/طلباتي/حذف الحساب) · نسيت كلمة المرور/البريد ← واتساب الدعم 21893158884 برسالة جاهزة + رابط استعادة آمن يولّده الدعم بعد التحقق · فروع (سوق الجمعة، النوفليين، السراج) · تيك توك · تذييل بعبارة «صنع بواسطة ابتكار».

**للإدارة (`/admin`):** لوحة معلومات حقيقية · الطلبات (بحث/تصفية/تحديث الحالة/تأكيد استلام المبلغ/سجل كامل) · المنتجات والأحجام والصور (تُضغط WebP في المتصفح) · الأقسام · الباقات ومحتوياتها · الإعلانات (عدة صور، فترات عرض) · الفروع (هاتف/عنوان/رابط خرائط/ساعات) · العملاء وطلبات الدعم · **بوابات الدفع** · الإعدادات (الشعار، أرقام التواصل، ترتيب أقسام الرئيسية، من نحن والسياسات، التوصيل) · الفريق (موظف/مدير) وسجل العمليات. تعمل على الهاتف (قائمة منزلقة وجداول تتحول لبطاقات).

## ما يحتاج منك (لا أخترعه)

| البند | الحالة |
|---|---|
| **الشعار الأصلي** | لم يصل ملف الشعار. يظهر شعار نصي مؤقت بنفس الألوان. ارفع الأصلي من **الإعدادات ← الشعار** (أو ضعه في `public/assets/logo.png`)؛ يُقصّ دائريًا بخلفية عنابية بـ CSS دون تعديل الملف. |
| عناوين وهاتف وروابط خرائط **النوفليين والسراج** (وعنوان سوق الجمعة) | لم تُعطَ → تُترك فارغة ولا تظهر أزرار الاتصال/الاتجاهات إلا عند إدخالها من **الفروع**. |
| **الدفع الإلكتروني** | جاهز للربط: أضف مفاتيح بوابتك من **بوابات الدفع** — راجع [`docs/PAYMENTS.md`](docs/PAYMENTS.md). الدفع عند الاستلام يعمل الآن. **لم تُجرَّب أي بوابة على حساب تاجر حقيقي** (اختُبرت مقابل خادم وهمي بنفس العقد). |
| المنتجات والأسعار والباقات والإعلانات | تُدخل من الإدارة. |
| نصوص «من نحن» والسياسات | مسودات عامة؛ راجعها قبل الاعتماد. |
| استعادة كلمة المرور بالبريد | غير مفعّلة (لا مزوّد بريد). المعتمد: واتساب الدعم + رابط يولّده المدير. |

## النشر (VPS + Docker)

```bash
cp .env.example .env     # عدّل SITE_URL و ADMIN_* و APP_SECRET
docker compose up -d --build
```

ضع Caddy أو Nginx أمام الحاوية للـ HTTPS (مثال Caddy: `example.com { reverse_proxy 127.0.0.1:3000 }`) واترك `TRUST_PROXY=1`.
البيانات (قاعدة SQLite والصور والمفتاح `.secret`) في المجلد `/data` — **خذ نسخًا احتياطية منه**.

## الأمان باختصار

كلمات المرور scrypt · جلسات عشوائية مخزّنة مُجزّأة · كوكي `HttpOnly`+`SameSite=Lax`+`Secure` في الإنتاج · حماية CSRF بفحص الأصل · CSP صارمة (`script-src 'self'`) · تحديد معدل للدخول والطلبات والبحث · كل سعر وإجمالي يُحسب على الخادم · رفع الصور بفحص البايتات · مفاتيح البوابات مشفّرة ولا تصل للمتصفح · حماية SSRF لاتصالات البوابات · حذف الحساب يزيل البيانات الشخصية من الطلبات ويُبقي المبالغ للمحاسبة.

## الاختبارات

```bash
npm test            # 32 اختبار API (مصادقة، تسعير، طلبات، دفع، بوابات، أمان…)
npm run test:e2e    # 39 خطوة في متصفح حقيقي: الإدارة تبني الكتالوج والعميل يطلب ويدفع (Sandbox) ويحذف حسابه
node tests/shots.js # لقطات الصفحات (جوال + كمبيوتر) وفحص أخطاء JS والتمرير الأفقي
```

متطلب e2e: Playwright (`npx playwright install chromium`).

## ملاحظة على المتطلبات

المتطلب الأول كان «بانر ثابت بلا تحريك»؛ بطلبك اللاحق صار البانر **يتبدّل تلقائيًا كل 2.5 ثانية** بصور تضيفها من الإدارة (يتوقف عند المرور بالمؤشر/التركيز/اللمس ويحتوي زر إيقاف، ولا يتحرك تلقائيًا لمن فعّل «تقليل الحركة» في جهازه).
