# النشر على Cloudflare (Workers + D1) — بلا سيرفر

المتجر يعمل **بالكامل على Cloudflare**: الكود على **Workers**، والطلبات والمنتجات والحسابات في قاعدة **D1** (يُنشئها Cloudflare لك تلقائيًا)، والصفحات الثابتة من شبكة Cloudflare مباشرة. لا سيرفر ولا Docker ولا قاعدة بيانات تُجهّزها بنفسك.

> ما اختُبر: كل الكود على Cloudflare محليًا بـ `wrangler dev` (D1 محلية بنفس محرك SQLite): 11 اختبار خاصًا بالـ Worker + سيناريو المتصفح الكامل (إدارة + عميل + دفع تجريبي) كلها نجحت. **لم يُجرَّب على حسابك الحقيقي** (لا أملك الوصول إليه)، فجرّب أول نشر بنفسك قبل الإعلان عن المتجر.

## الطريقة 1 — من لوحة Cloudflare بلا طرفية (أسهل)

1. ارفع هذا المجلد إلى مستودع GitHub (أو استخدم المستودع الموجود).
2. Cloudflare ← **Workers & Pages** ← **Create** ← **Import a repository** ← اختر المستودع.
3. **Root directory** = `alem-al-bklawa` (المجلد الذي فيه `wrangler.jsonc`). اترك أمر النشر الافتراضي `npx wrangler deploy`.
4. اضغط **Deploy**. يقرأ Cloudflare ملف `wrangler.jsonc`، **وينشئ قاعدة D1 تلقائيًا**، ويعطيك رابطًا مثل `https://alem-al-bklawa.<حسابك>.workers.dev`.

## الطريقة 2 — أمر واحد من الطرفية

```bash
cd alem-al-bklawa
npx wrangler@4 deploy        # أول مرة يفتح المتصفح لتسجيل الدخول لحسابك ثم ينشئ D1 وينشر
```

## أول فتح (مهم: افعله فورًا)

افتح `https://…workers.dev/admin` ← يظهر نموذج «إعداد المتجر لأول مرة» ← أنشئ حساب المدير (بريد + كلمة مرور). بعدها يُغلق النموذج نهائيًا. الجداول والأقسام والفروع تُنشأ تلقائيًا عند أول طلب.

⚠ **من يفتح الصفحة أولًا يصبح المدير.** لذلك افتح `/admin` مباشرة بعد النشر. لمن يريد حماية إضافية: أضف المتغير `SETUP_CODE` (أي نص، مثل `K7M2-Q9XA`) في **Worker ← Settings ← Variables and Secrets** *قبل* الفتح الأول، فيُطلب الرمز في النموذج.

## حدود الخطط (اقرأها)

| | Workers Free | Workers Paid ($5/شهر) |
|---|---|---|
| الطلبات | 100 ألف/يوم (الملفات الثابتة مجانية وغير محسوبة) | غير محدودة |
| وقت المعالج لكل طلب | **10 ms** | 30 ث (قابل للرفع) |
| D1 | 5 مليون قراءة صف و100 ألف كتابة يوميًا، 500MB للقاعدة | أعلى بكثير |

* **تسجيل الدخول/إنشاء الحساب يحسب تجزئة كلمة المرور (PBKDF2)** وهذا يستهلك معالجًا. الافتراضي هنا 50 ألف دورة (≈ 8 ms) كي يعمل على الخطة المجانية، لكنه قريب من حدّها (10 ms). إن ظهر لك **خطأ 1102** عند الدخول: إمّا رقِّ إلى **Paid**، أو خفّض `PASSWORD_ITERATIONS` إلى `20000` من نفس صفحة المتغيرات. على Paid يمكنك رفعه (مثلًا `100000` أو أكثر) لحماية أقوى. التغيير يطبَّق على كلمات المرور الجديدة فقط.
* **الصور** تُخزَّن في D1 (≤ 1MB للصورة؛ المتصفح يضغطها WebP ≤ 1200px تلقائيًا فتكون عادةً أقل من 200KB). مئات الصور مقبولة؛ آلاف الصور الكبيرة تستحق نقلها لاحقًا إلى R2.
* الخطة المجانية تُوقف الاستعلامات عند تجاوز حصة D1 اليومية (تعود عند منتصف الليل UTC). متجر صغير/متوسط لا يقترب منها.

## متغيرات اختيارية (Worker ← Settings ← Variables and Secrets)

| المتغير | الاستخدام |
|---|---|
| `APP_SECRET` (**Secret**، 32 حرفًا أو أكثر) | يشفّر مفاتيح بوابات الدفع. **أضفه قبل إدخال أي مفتاح بوابة.** بدونه يُنشأ مفتاح تشفير عشوائي ويُحفظ داخل القاعدة نفسها (حماية أضعف: من يملك نسخة القاعدة يملكه). إن أضفته *بعد* حفظ مفاتيح بوابة فأعد إدخالها. |
| `SITE_URL` | عنوان ثابت للمتجر (مثل `https://alem.ly`). الافتراضي: العنوان الذي يفتحه الزائر. |
| `SETUP_CODE` | رمز لنموذج أول إعداد (انظر أعلاه). |
| `PASSWORD_ITERATIONS` | تكلفة تجزئة كلمات المرور (انظر الحدود). |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | بديل لنموذج أول إعداد: ينشئ المدير تلقائيًا. |

## نطاقك الخاص

Worker ← **Settings ← Domains & Routes ← Add ← Custom domain** (النطاق يجب أن يكون على Cloudflare). يصدر SSL تلقائيًا.

## الدفع الإلكتروني

بعد النشر: **الإدارة ← بوابات الدفع** ← أضف مفاتيح بوابتك (راجع [`PAYMENTS.md`](PAYMENTS.md)). رابط الـ Webhook الذي تضعه عند مزوّد الدفع يظهر في نفس الصفحة: `https://نطاقك/api/payments/webhook/<رقم>`. الدفع عند الاستلام يعمل دون إعداد. بوابة «Sandbox» التجريبية غير موجودة في الإنتاج عمدًا.

## النسخ الاحتياطي

```bash
npx wrangler d1 export alem-al-bklawa-db --remote --output backup.sql   # كل الطلبات والمنتجات والحسابات والصور
```
وفي لوحة Cloudflare ← **D1** ← قاعدتك ← **Time Travel** لاسترجاع القاعدة إلى لحظة سابقة. جدول نسخة دورية خارج Cloudflare إن كانت الطلبات مهمة لك.

## التحديث

دفعٌ جديد إلى GitHub يعيد النشر تلقائيًا (الطريقة 1)، أو أعد `npx wrangler@4 deploy`. قاعدة البيانات تُرقّى تلقائيًا (ملفات `server/migrations`) ولا تُمسح.

## ما يختلف عن نسخة Node

نفس الكود تمامًا (`server/`) يعمل في الحالتين؛ الفروق في الطبقة السفلية فقط: D1 بدل SQLite المحلي، الصور في D1 بدل القرص، تحديد المعدل في D1، ومفتاح التشفير من `APP_SECRET` أو من القاعدة. اختبارات `npm test` (Node) و`npm run test:worker` و`npm run test:e2e:worker` (Cloudflare محليًا) تغطي الاثنين.

## خيار متقدم: سيرفر Node + Cloudflare Tunnel

إن فضّلت تشغيل المتجر على سيرفرك (VPS/جهاز Docker) وCloudflare أمامه كنطاق وSSL وCDN بلا فتح منافذ:

1. **على السيرفر** (يلزم Docker): `cp .env.example .env` وعدّل `SITE_URL` (https) و`APP_SECRET` و`TUNNEL_TOKEN`.
2. **Cloudflare** ← Zero Trust ← Networks ← Tunnels ← *Create a tunnel* ← انسخ التوكن؛ *Public hostname* ← Service `HTTP` ← `store:3000`.
3. شغّل: `docker compose -f deploy/cloudflare/docker-compose.yml --env-file .env up -d --build`، ثم اقرأ رمز الإعداد من `… logs store` وافتح `/admin`.
4. النسخ الاحتياطي: `… exec store node scripts/backup.js /data/backups` ثم انسخ `/data` خارج السيرفر. التحديث: `git pull && docker compose … up -d --build`.
